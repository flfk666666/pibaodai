# 地区收入参考分与竞争力摘要 v0.3

本模块将同一份税前收入放到不同地区的工资坐标中比较：统一成人民币年化金额，再计算相对倍数和项目参考分。它补充现有`anchored-review-v0.2`六轴报告，不改变主轴权重、分值或事实档案。

当用户接受名义汇率粗比较时，直接完成换算与判断。年龄、统计范围或奖金口径不完全一致时标明差异，不再只列外币金额、不给分，或以缺少PPP调整为由阻塞交付。

## 1. 两种60分不能混用

| 分数 | 60表示什么 | 不表示什么 |
| --- | --- | --- |
| 主六轴规则分 | 达到该子项声明的“基本够用”条件 | 人群平均、当地收入水平、人口百分位 |
| 地区收入参考分 | 本人税前年化收入恰好等于这一条所选工资参照 | 综合能力及格、人口第60百分位、当地求职报价 |

地区模块版本为`regional-income-v0.3`。报告主版本仍可为`anchored-review-v0.2`，不为增加地区模块重写旧档案或旧报告架构。

## 2. 先统一期间与币种

每条工资参照保留原金额、币种、统计期间、均值或中位数、税前后、年龄范围和来源。比较使用本人税前年化收入；缺少税前口径时明确缺口，不擅自把到手工资当税前。

年化系数固定为：年工资×1，月工资×12，周工资×52。月薪和周薪乘系数得到的是“年化参照”，不证明受测者或样本实际领取了整年同样工资；原统计中的奖金、社保等定义仍需保留。

汇率统一记为`每1单位外币对应多少CNY`。所有地区使用同一汇率日期与来源；若使用以欧元为基准的官方交叉表：

```text
外币兑人民币 = CNY/EUR ÷ 外币/EUR
参照人民币年化金额 = 原工资金额 × 年化系数 × 外币兑人民币
```

`CNY`汇率为1。汇率须为有限正数；本人收入可为明确的0，参照工资必须大于0。缺少必要金额或汇率时保留具体缺口，不靠记忆编一个换算值。

标题写“人民币名义汇率口径”。**统一币种不等于统一购买力**：本模块不自动调整物价、税负、住房或公共服务，也不把名义收入分称为生活质量分。工资统计年份和汇率日期分别显示，不把旧年工资悄悄写成当期工资。用户选择这种比较后，不需要再征求一次“允许不公平比较”的确认。

## 3. 可复算的参考分

令`r = 本人税前年化人民币 ÷ 参照税前年化人民币`：

```text
地区收入参考分 = max(0, min(100, 60 + 20 × log2(r)))
```

本人收入明确为0时分数为0，未知收入不当0。界面显示四舍五入的整数分，同时保留计算使用的金额与倍数。

| 本人收入/参照 | 参考分 | 可用解释 |
| --- | ---: | --- |
| 0.125倍及以下 | 0 | 名义收入明显低于所选参照；不是人口最低层的精确排名 |
| 0.5倍 | 40 | 约为参照的一半 |
| 1倍 | 60 | 与这条参照接近 |
| 2倍 | 80 | 约为参照两倍 |
| 4倍及以上 | 100 | 达到本项目显示上限；仍显示实际倍数 |

该对数映射是项目公开选择，目的是让每翻倍对应20分，不是官方量表、预测模型或百分位。高倍数封顶后仍须显示如“5倍”等实际比例，不能让100分掩盖不同收入差距。

同一地区有私营/非私营、均值/中位数或多个国家样本时，逐条换算和评分。可显示“不同参照所得分数范围”，但不取范围中点假装统一分；该范围也不是统计置信区间。欧洲注明具体覆盖范围，东南亚国家分别列出，不简单平均成整个区域的工资或分数。

## 4. 同龄偏好与粗比较并行

继续优先匹配年龄±3岁及受测者适用人群；只有出生年时不编精确足岁。调查年份、年龄组和出生队列要能对应，不把历史25—29岁组一律称为今天同龄人。

若只找到近龄组、广龄数据或全体就业者，清楚标注后仍可以在用户接受的粗比较模式下计算名义收入参考分。这不会生成精确同龄分位，也不证明职业、性别、税负和福利已完全匹配。不能以“数据不完美”替代已能完成的年化与币种换算。

## 5. 地区竞争力摘要要给判断

每个地区先给收入分、人民币年化参照、本人相对倍数和一句直接结论，再写：

- **收入位置：** 相对哪条均值或中位数高/低多少，所选口径会怎样影响结论。
- **已有优势：** 根据实际案例指出专业、工具协作、交付、语言或可调用资源，避免把职位名称当能力证明。
- **主要短板：** 只写材料支持的限制。目标岗位语言、工作资格或当地支持未知时说待确认，不能自动记成0分；也不能由国籍或地区标签推断能力。
- **下一步：** 给一项能检验该地区适配的具体产物或动作，如目标岗位语言的一页项目交接及问答、匿名岗位要求与已有作品的逐项对照、可用合作资源清单。不要只说“提升英语、积累经验”。

摘要可以毒舌，但要指出可核对的现实落差。名义收入有优势不等于当地岗位会给同样收入；收入较低也不等于专业能力差。页面应明确这是“保持当前收入作地区对照”的情境，不擅自预测搬迁后的薪资。

不把六轴、汇率、语言、工作资格和家庭资源随意加权成一个地区综合总分。量化的是地区收入坐标；其余条件给具体的适配判断。主雷达保持原规则，切换地区不改变主六轴分数。

## 6. 数据与计算接口

`scripts/regional_income.py`提供：

```text
compare_income(self_annual_cny, reference_amount, currency, frequency, cny_per_unit)
calculate_benchmarks(benchmarks)
```

`benchmarks`对象需要以下字段：

| 字段 | 内容 |
| --- | --- |
| `version` | 固定`regional-income-v0.3` |
| `self_annual_cny` | 本人税前年化人民币金额；保留来源及事实日期 |
| `fx.rate_date` | 所用汇率的实际日期 |
| `fx.cny_per_unit` | 每1单位外币对应CNY的币种映射 |
| `fx.source_url` | 实际取数来源，不伪造核验 |
| `groups` | 地区组，含`id`、`label`与`income_rows` |
| `groups[].income_rows[]` | `label`、`source_amount`、`currency`、`frequency`、`source_url`、`age_note`；同时保留统计期间与工资定义 |
| `groups[].regional_score` | 该地区的`summary`、`verdict`、`strengths`、`bottlenecks`与`next_step`，均须对应已知材料 |

地区资料放在独立`benchmarks`对象中；旧报告的`regions`背景资料可以保留，不参与六轴合成。渲染器调用计算器复算地区金额、倍数与收入参考分，不能先手写一个分数再找理由。完整字段及虚构格式演示见[CLI说明](cli.md#地区收入换算与参考分-v03)。

公开示例只用明确编写的数据，不含真人收入、真实地区得分或私人路径。真实JSON、HTML、截图和来源快照仍留在已核实的私人位置。
