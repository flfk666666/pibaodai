# 现实提升与评测维护

协议标识：`recommendation_protocol: real-life-improvement-v1`。

本协议整理建议的用途与交付结构，不改变v0.6权重、锚点、六维计算或v0.7联合条件。建议的价值是帮助本人改变现实能力、状态或处境；资料更完整只是让评阅更准确。两者应在页面分开呈现。

## 先判断建议到底改变什么

**现实提升**有一条完整的因果线：已有事实中的具体制约或可迁移优势 → 本人目标 → 可执行动作 → 生活中的结果。例如，短期事务无人接手时，落实并实际使用一条取送支持渠道，会改变资源可调用性。

**评测维护**改变评价者掌握的资料：补问、查测量日期、留照片、更新余额、核统计口径、重算分数或保存档案。这些事情可以有用，但不能单独作为“你先改哪一件事”的答案。填写率、照片数量与报告完整度不是本人能力改善。

同一动作可能服务两个目的，要按实际结果区分。查清定期到账规则是盘点；若随后确实调整可用资金安排，才可能改善缓冲。写求助名单是准备；联系对象、达成可执行安排并在真实需要中履约，才建立了支持。日记可帮助检验作息调整，但“记录够天数”不等于恢复变好。

## 生成流程

1. **读取已有内容。** 对照对应项`construct`、`evaluation`、实际事实和本人目标，区分明确制约、已成立优势与未观察范围。分低不自动说明需要修正，分高也不要求再找一个缺点。
2. **选一个值得改变的结果。** 每轴以一个最小计划为主，可在步骤中容纳相关动作。明确短板时处理现实制约；表现已好时巩固、降低使用成本或迁移到本人需要的场景。没有已证短板，`current_gap`可直接写“未观察到明确不足，本计划用于巩固或应用已有能力”，并说明事实依据。
3. **联系本项标准。** `standard_basis`解释目标对应哪一项构念、哪种实际条件。它不是“做完自动得到某分”的承诺。数值容量、低负担状态与行为能力分别处理，不把更多消费、联系人、器材或副业数量当通用目标。
4. **写现实动作。** 步骤应让本人知道接下来如何做。需要跨轴支持时可以在文字中说明，但`target_items`只引用本轴项目。不要把模型设计、指标穷举或所有可能方案交回本人完成。
5. **用生活结果验收。** 看任务是否完成、限制是否减少、承诺能否兑现或帮助是否可调用。次数和时间可以作为试行周期，允许调整；它们不是评分锚点、疗效保证或医学达标线。
6. **把维护移出去。** 资料续问、复测、来源查证和保存提示放`assessment_maintenance`。确实影响当前建议且未被明确跳过的事实才补问；未知仍是未知，不先判低能力。

### 六轴的建议边界

| 轴 | 可改变的现实结果 | 不应强加的目标 |
| --- | --- | --- |
| A 外形条件与呈现 | 按本人偏好维护与搭配，让已有风格适配需要的场景 | 增高、迎合单一审美、必须买衣服或补照片 |
| B 身体功能与当前状态 | 提高恢复体验、普通任务的舒适性与持续性；必要时寻求合适专业支持 | 新极限纪录、靠硬扛证明精力、未评估就加大旧伤部位负荷 |
| C 思考与判断表现 | 风险匹配的核验、明确决策边界、处理干扰并回到行动 | 所有闲聊都做研究、以收集链接或答对新题代替实际判断 |
| D 实践与协作能力 | 完成交付、处理分歧与变化、把已有方法迁到本人选择的任务 | 单靠头衔、工作量或别人表扬验收；为了升级强行找更大项目 |
| E 个人经济与缓冲 | 改善本人选择下的可用缓冲、支出安排与偿付余地 | 必须有副业、统一存款月数、具体证券交易；把未知消费判成挥霍 |
| F 可调用资源与约束 | 需要发生时有适配人手、渠道、工具或退路 | 多社交、多联系人、维护一份漂亮清单；反复确认已成立家庭支持 |

已经高分的轴允许只给巩固或应用建议，不能编造新缺陷。目标工作语言、完整站姿或消费总额未测时，不把未知本身包装成需要改善的人格、能力或习惯。

## 报告字段

在完整报告顶层声明：

```json
{
  "recommendation_protocol": "real-life-improvement-v1"
}
```

A–F六个轴各自都有以下字段。字段值应具体、有事实依据，不能用空字符串、占位话或旧`actions`应付协议。

| 字段 | 类型与含义 |
| --- | --- |
| `improvement_plan.title` | 非空字符串，直接说明要改善或巩固的现实结果 |
| `improvement_plan.target_items` | 非空、无重复的项目ID数组；A轴只能A1–A6，以此类推 |
| `improvement_plan.current_gap` | 非空字符串，写已有事实中的制约，或诚实说明本次是优势巩固/迁移；未知不写成不足 |
| `improvement_plan.target` | 非空字符串，描述本人希望形成的行为、状态或处境 |
| `improvement_plan.standard_basis` | 非空字符串，联系所选项目的构念与条件，说明为何这件事有用；不承诺达到某分 |
| `improvement_plan.steps` | 1—3条非空字符串，写本人可执行的现实动作 |
| `improvement_plan.success` | 非空字符串，用现实结果验收；不是补材料、填表或评分上涨 |
| `improvement_plan.sources` | 数组，可为空；每条为非空`title`和HTTPS `url`，只放实际核验且支持建议的来源 |
| `assessment_maintenance` | 字符串数组，可为空；单独保存评阅所需的资料、日期、复测或口径提示 |

声明该协议的完整报告需要六轴全部符合结构要求，不能少一轴时静默退回旧`actions`。旧报告可保留`actions`继续阅读；新增协议报告移除非空旧`actions`，以`improvement_plan`交付提升内容，维护提示单列，省略`assessment_maintenance`等同于空数组。不要改变旧报告来伪装它已符合新协议。

健康、财务、法律等高影响建议应先核验适合该主张的一手来源，必要时缩小建议范围。来源没有证明个体一定受益，不能写成疗效保证；统计或指南也不证明本项目权重合理。普通行为试行可以标明是项目建议，`sources`为空，不伪造研究背书。不得从图片或低分推断疾病。

## 虚构成人案例：从“写清单”到可用帮助

以下是**编写的虚构示例**，不是用户记录，也不是实际服务推荐。成人甲明确说：“我生活能自理，临时不方便出门时需要有人送生活用品。目前只有到时再找服务的想法，没有安排过，也不知道谁能接。”这是假设中明确说出的情况，不能由真人未回答就照搬。

对应F3“事务与照护人手”的目标是建立普通短期需要下可实际实行的帮助，时点、费用和范围适配。它不要求扩大社交圈，也不代表本人整体资源都弱。

| 不合格建议 | 合格改写 |
| --- | --- |
| “补充三名联系人，下次再评F3。” | 先选生活用品取送这一个需求，联系可覆盖地址和所需时段的对象，达成具体安排，再用一次本来就需要的小任务实际使用它。 |
| “保存清单和服务截图就算提升完成。” | 验收看真实需要中是否按约完成、交接是否可行；清单和截图仅帮助记住安排。 |
| “F3未知，所以你缺乏照护能力。” | 若本人没有说支持不足，只写未核实可调用性；不据缺材料诊断短板。 |
| “连续做满两周就能升到75。” | 普通短期支持是否真的可实行决定后续评阅；周期只是试行建议，完成动作不保证升分。 |

机器可读[虚构F3片段](../examples/improvement-actions-fictional.json)只示范F轴计划与维护字段，**不是完整六轴报告，不能直接当完整报告交给renderer**。完整运行时应基于同一个虚构人物的完整事实为A–F各写计划；不能复制这一轴六遍，也不能补造真人答案。该示例只演示方法结构，没有真实履约或个人改善结果。
